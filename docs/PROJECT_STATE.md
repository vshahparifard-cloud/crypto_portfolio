## ARCH
api: fastapi, stateless, N replicas. reads prices ONLY from redis cache. never calls external APIs.
worker: arq = market_poll(5m) | candle_aggregator(5m) | chart_backfill(on new coin) | alert_evaluator(on each price sample) | telegram_sender(loop) | email_sender(loop) | coin_list_sync(1d)
bot: aiogram webhook at POST /api/v1/telegram/webhook/{secret}
price_flow: coingecko /coins/markets?ids=<tracked ∪ referenced> (1 req/5m, all coins in one resp) -> redis price:{coin} + market:top50 + pubsub ch:prices -> price_snapshots row/coin -> alert_evaluator -> alert_events(outbox) -> telegram_sender -> telegram.sendMessage
chart_flow: price_snapshots -> candle_aggregator -> ohlc_candles(1h,1d) -> GET /market/coins/{id}/chart (redis ttl 60s). pre-launch history: coingecko /market_chart once per coin (chart_backfill).
email_flow: register|forgot -> email_tokens(hashed, 24h, single use) + email_outbox -> email_sender -> smtp
budget: 8640(poll) + 30(coin list) + ~120(backfill) = ~8790/10000 per month. POLL_INTERVAL=300s is the cap-defining constant; do not lower it without a paid key.
web_live: SSE GET /market/stream <- redis pubsub
locks: alert_evaluator holds redis lock `lock:evaluator` (single active instance)
health: each worker stamps redis `hb:{worker}`; /health reports staleness

## GOTCHAS
- coingecko free = 10k req/month HARD cap. 5m poll already spends 8.6k. every new call site must be added to the budget line in ARCH first.
- one /coins/markets response carries all 50 coins. never loop per-coin for prices; that is the #1 way to blow the cap.
- alert latency is <=5min by design (owner decision D1). a move that crosses a threshold and returns between two samples produces NO alert. say this in the ui, not just in docs.
- pct_change alerts need the price N minutes ago -> redis zset of the last ~24 samples per coin, not a postgres query.
- poll failure leaves a gap: candle_aggregator must tolerate missing samples (do not interpolate; mark the candle partial).
- password reset / forgot must return the same response for known and unknown emails (no account enumeration).
- telegram: 30 msg/s global, 1 msg/s per chat. sender must throttle or messages get 429 + retry_after.
- SSE behind proxy needs buffering off (caddy: flush_interval -1).
- redis pubsub is fire-and-forget: never the source of truth for alerts; evaluator reads the cached value.
- POLL_INTERVAL_SECONDS=300 is the floor on the free plan. 180s => ~14.4k req/month => cap blown mid-month.
- is_tracked is owned by sync_top_list only; the 5m poll must never re-track a demoted coin.
- a fresh alert stays quiet until it has seen two samples (no previous price => no crossing). intentional.
- the post-commit hook amends; the state file writes `commit=HEAD` because the final sha is not known yet.
